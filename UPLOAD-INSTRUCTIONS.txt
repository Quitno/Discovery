PATAMAHALI — ORIGINAL SITE RESTORE + PUBLIC-SOURCE RENTAL PILOT

IMPORTANT: This package is rebuilt from your original Discovery-main (1).zip.
It is NOT the earlier redesigned house-hunting pilot. The original homepage,
customer navigation, existing property cards, organic content, animations,
current property listings and original verification process are preserved.

WHAT THIS BUILD ADDS
- Eight public rental adverts from Kenya Property Centre, including apartments,
  a five-bedroom family house and two four-bedroom townhouses in Ruiru.
- Their cards appear as an additional section in the existing /homes residential
  finder. Original owner/agent listings remain in the original listing cards.
- Cards include the exact advert photo URL, asking rent, bedrooms/bathrooms,
  location, named advertiser, public reference, check date and a link to the
  original advert.
- The label is "Advert source checked", NOT PataMahali "Property verified".
  The adverts were visible on their source pages on 2 November 2026. PataMahali
  has not independently inspected these homes, verified the advertiser's
  authority or confirmed current availability.
- A new Admin > Source listings page removes one imported advert or all eight.
  These records are stored separately from partner listings. The per-ad seed
  markers remember deletions so removed adverts do not return after restart.
- The SEO titles and descriptions for the home page, residential finder and
  county/constituency/locality pages are improved. Existing robots.txt,
  sitemap.xml, canonical URLs, page body, homepage layout and animations remain.
- A one-time safe cleanup removes only sample records created by the previous
  pilot under the exact reserved demo account email
  patamahali-demo-owner@example.invalid. It does not delete any other owner's
  records, users, properties, uploaded images or documents.

DEPLOY THIS BUILD
1. Back up the production database using the site's admin backup function and
   keep a copy outside Render.
2. Extract this ZIP and open the Discovery-main folder.
3. Copy ALL files and folders inside Discovery-main into the ROOT of your
   existing GitHub repository connected to Render. Replace matching source
   files and add new files. Do not create a nested Discovery-main folder.
4. Commit and push to the same branch Render already deploys.
5. Keep your existing Render environment variables and persistent disk. Do not
   delete /var/data, the production SQLite database, uploaded photos/documents,
   or secrets. The ZIP does not contain your production database.
6. After deployment, test /, /homes,
   /homes?category=residential&location=Ruiru,
   /homes?category=residential&location=Baba%20Dogo, /robots.txt and
   /sitemap.xml. Sign in to Admin and open Source listings.
7. When ready, remove an advert or all imported adverts under Admin > Source
   listings. Do not use the ordinary Properties delete controls for this.

IMPORTANT LIMITS
- Public source adverts are not a live feed. Prices or availability may change,
  and adverts may be withdrawn after the check date. Re-open the original source
  before relying on any details.
- Images are hotlinked from the source platform's image host, not re-hosted.
  A browser or source-host policy may block external image display. Obtain any
  needed permission for long-term use of third-party photographs.
- This workspace cannot inspect your production database, so it cannot prove
  that none of these eight source adverts duplicates one of your own listings.
  Check the finder after deployment and remove any duplicate under Admin >
  Source listings. Your own listing rows are not modified by this code.
- No code can guarantee Google ranking or immediate indexing. After deployment,
  submit the existing sitemap in Google Search Console and inspect the home,
  residential finder and useful county/locality pages for indexing and errors.
- This workspace could not launch a live Flask server; run the post-deployment
  smoke tests above before announcing the updated site.
